# patch_note 작성 지침

> div-tracker의 모든 변경 이력을 담는 폴더. **프로그램을 파악할 때는
> DIV_TRACKER_KNOWLEDGE.md(현재 상태의 정본)와 함께 이 폴더의 최신 노트들을 반드시 읽는다.**
> 역할 분담: 지식 문서 = "지금 어떻게 동작하는가" / patch_note = "언제 무엇이 왜 바뀌었는가".

## 언제 쓰나

다음 중 하나라도 바뀌면 노트 1개를 작성한다 (한 세션의 연관 변경은 노트 1개로 묶는다):

- 코드(`fetch_rank.py`, `docs/index.html`, `.github/workflows/daily.yml`)
- `watchlist.csv` (종목 추가·제거·교체)
- 순위 공식·가드·알림 규칙 등 설계 (이 경우 지식 문서 §결정 로그도 함께 갱신)
- 문서 구조·운영 방식

오타 수정 등 동작에 영향 없는 변경은 생략 가능.

## 파일명

`vX.Y.md` — 버전 번호제(예: `v1.1.md`). 직전 노트에서 0.1씩 올리고, 구조가 크게 바뀌는
변경이면 앞자리를 올린다(v2.0). v1.0은 2026-08-15 최초 구축(별도 노트 없음 — 지식 문서
§8 참조)이고, 첫 노트가 v1.1. 날짜·주제는 첫 줄 제목에 쓴다: `# vX.Y (YYYY-MM-DD) 제목`.

## 형식 (필수 항목 4개)

```markdown
# YYYY-MM-DD 제목

## 변경
무엇이 바뀌었나 — 파일·항목 단위로 구체적으로.

## 이유
왜 바꿨나. 근거 수치는 실측(출처·시점)과 추정을 구분해 표기.

## 영향
동작·화면·알림에 생기는 차이. 코드 변경 없으면 "코드 변경 없음" 명시.

## 검증
확인한 방법(--selftest 통과, CSV 파싱, Actions 로그 등). 안 했으면 "미검증"이라고 쓴다.
```

## 원칙 (지식 문서 원칙의 적용)

- 검증 불가한 내용·과장 금지. 실측과 추정을 항상 구분.
- 토큰·시크릿(TG_TOKEN 등)을 절대 쓰지 않는다 (repo는 public).
- 근거 없는 매직넘버가 들어간 변경이면 그 근거 논의 내용을 노트에 남긴다.
