# v1.2 (2026-08-18) 수집 실패 종목 직전값 보존(⏸ stale)

## 변경
- `fetch_rank.py`: `preserve_failed()` 추가 — 수집 실패 종목은 행을 지우는 대신 직전 실행의
  행을 `stale: true` + `stale_since`(마지막 성공 시각, 연속 실패에도 최초 시점 유지)로 보존.
  순위도 직전값 기준으로 계속 산출. fails 목록은 "신선한 행"이 생겨야 해제되도록 보정.
- `docs/index.html`: stale 행은 흐리게(⏸ 직전값 + 날짜 병기, 툴팁 설명), 읽는 법 한 줄과
  "표 읽는 법" ⑥항에 설명 추가.
- selftest에 실패보존 4케이스 추가(보존·이벤트 침묵·최초 실패 시점 유지·복구 시 알림 정상).

## 이유
2026-08-18 KR 실행에서 7종목(맥쿼리인프라 + 국내 ETF 6개 전부) 수집 실패 실측 — 실패 종목이
표에서 조용히 사라져(각주에만 표시) "밴드 99 종목이 하루 만에 증발"로 보였고, 직전 상태까지
지워져 복구 시 `band_events()`가 첫 실행 취급 → 싼편 진입 알림도 침묵하는 문제 확인.
실패 패턴은 watchlist상 연속 블록 2개와 일치 + 전날 실행은 22종목 전부 성공 → 야후 429
스로틀(§6 기지 이슈)로 추정(Actions 로그로 확정 필요). 보존 방식이 "고정 리스트에서 그날그날
싼 것을 보여준다"는 도구 성격·표시 정직성·비치명 설계에 부합.

## 영향
- 수집 실패가 나도 표의 종목 구성이 유지됨(흐린 행 + 날짜). 복구 시 밴드 80 교차·🚩 전환
  알림이 직전값 기준으로 정상 동작.
- 이미 사라진 7종목은 소급 복구 불가(직전 행이 data.json에 없음) — 야후가 응답하는 다음
  실행에서 신선값으로 자연 복귀.
- 데이터 스키마에 `stale`/`stale_since` 필드 추가(구버전 페이지는 무시하므로 배포 순서 무관).

## 검증
- `--selftest` 통과(기존 전 항목 + 실패보존 4케이스, 오프라인 실측).
- index.html 스크립트 구문 검사 통과(node --check). 실브라우저 렌더는 미검증 — 다음 실행 후
  확인 권장.
